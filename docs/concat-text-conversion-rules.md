# Function-specific text conversion contracts

The unregistered deterministic module `crates/msduck-sql/src/concat_text_conversion.rs` supplies conversion contracts for later adapters. It does not change server behavior or register an SQL function. Its authority is the complete four-run [text conversion reference](concat-text-conversion.md), merged in PR #815 at `207e051e655409e1d5d6ba24fbb675b3a9592436`; fixture SHA256 `4ef8ebf227b9dae4e1132196c6a04791d135df0fb69607eac886a0e6784fcc80`.

`contract` takes the function, original logical source declaration, explicit conversion domain and optional style. It takes no current value or NULL indicator. A contract retains that original declaration: an integer or binary source never becomes a character declaration to bypass another module's conversion barrier. Allocation lengths are target units (ANSI bytes or UTF-16 units), separate from wire byte lengths, flags and collation metadata. CONCAT_WS returns a source contribution, not a complete expression descriptor. Its caller still owns separator repetition, literal companion contributions, promotion, capping and nullability.

CONCAT_WS scalar allocations are 1 for BIT, 4/6/12/24 for integer families, 23 for REAL/FLOAT, 41 for captured decimal declarations, and 40 for currency, temporal and GUID families. Character source allocations retain their declared units; TEXT/NTEXT retain MAX. Binary allocation is its declared byte width for ANSI, half rounded up for Unicode reinterpretation. These are direct function allocations, not general CAST widths or current formatted lengths. TRANSLATE bounded output instead allocates 8000 ANSI bytes or 4000 UTF-16 units; captured MAX character/binary sources stay MAX. Native Unicode source declarations require the Unicode domain even with ANSI mappings. XML/SQL_VARIANT/IMAGE function rejection numbers, and TRANSLATE TEXT/NTEXT rejection, remain explicit.

Only captured declarations are admitted: character length 10 or MAX, BINARY lengths 2/10, VARBINARY lengths 2/10/8000/MAX, seven retained decimal precision/scale combinations and temporal scales 0/2/3/7. Other valid declarations return `Unsupported::Declaration`. Unknown codepages/domains and every explicit style return unsupported. NULL does not loosen any declaration/domain check. These deliberate limits can be expanded by separately captured evidence.

`binary_text` converts already-stored bytes in an explicit CP1252 or UTF-16LE domain. It preserves NULL, NULs and isolated UTF-16 units. `0x4142` is ANSI `AB` or Unicode U+4241; an odd final byte is padded with a zero high byte. Fixed BINARY must already have its declared padding, and oversized/short fixed inputs fail rather than being repaired. Inputs above 16 MiB fail before allocation. MAX remains an allocation property even for short or NULL values. The function performs no TRANSLATE mapping or CONCAT_WS joining/truncation.

The existing verified core CP1252 decoder is reused. Numeric, temporal and GUID formatting has no implementation here: captured width and example text do not establish rounding, exponent boundaries, locales or styles. Calling the binary converter on those declarations returns `Unsupported::Format`, including for NULL. Later adapters need honest explicit formatting evidence instead of treating already formatted text as a character source.

The focused tests embed the unregistered module and compare all applicable family allocations/rejections in all four retained runs, source-position and typed-NULL repetitions, both conversion domains, prepared descriptor stability and native binary bytes against function values. The long odd-byte MAX probe checks actual translated retained text separately from pre-translation conversion. Unsupported declarations/styles/domains, fixed storage validation, isolated UTF-16 units, forged contracts and input bounds are independent regressions. Runtime adapter integration and uncaptured conversion domains remain separate work.
