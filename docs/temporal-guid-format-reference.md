## Original declarations and exact stored evidence

Every input retains original SQL text, declaration, language, DATEFORMAT/DATEFIRST and independent role. The native role returns the source, `CONVERT(VARBINARY(MAX), source)`, and family-appropriate integer DATEPART fields. DATE retains year/month/day; TIME retains hour/minute/second/nanosecond; date-time families retain both; DATETIMEOFFSET also retains TZOFFSET. GUID retains its exact mixed-endian native binary. Source construction failures remain error records in every role.

Native driver dates are retained as observed carriers, including the driver's floating `nanosecondsDelta`, but no exact ticks or offset are reconstructed from them. A +14:00 DATETIMEOFFSET example stores local 2024-02-29 with TZOFFSET 840 while its decoded date is UTC 2024-02-28; the original source SQL, native binary and local DATEPART fields remain distinct. DATETIME's native binary retains its exact 1/300-second storage counts even when DATEPART/displayed milliseconds are rounded. SMALLDATETIME's native binary retains stored minute units. These are SQL conversion storage bytes, not a claim that the observer captures every raw ROW packet byte.

The orthogonal matrix has 366 typed SQL inputs and 15 separately requested roles per input (5,490 records), plus three session records, 55 prepared controls and two server/reuse records. The typed inputs are:

- 102 modern/GUID inputs in `us_english`: TIME, DATETIME2 and DATETIMEOFFSET scales 0 through 7, each with a day-end fractional carry input, a midnight/trailing-zero input and typed NULL; twelve DATE month samples plus minimum/maximum/leap-day/NULL; DATETIME2(7) extrema; seven DATETIMEOFFSET(7) sign/UTC-local-boundary inputs; and zero/all-FF/asymmetric/lowercase/NULL GUIDs.
- 88 legacy inputs in each of `us_english`, French and German: both DATETIME and SMALLDATETIME across all twelve months and midnight/noon/23-hour values, typed NULL, plus eight DATETIME range/1/300-second carry inputs and six SMALLDATETIME range/minute-rounding inputs.

Every role is independent: native stored parts; default CAST to VARCHAR(MAX)/NVARCHAR(MAX); explicit CONVERT style 0 and 121 to both domains; TRANSLATE with ANSI/Unicode empty mappings; and CONCAT_WS first-source, separator and last-source positions in both domains. No assumption equates default CAST with explicit style 0, or function-specific implicit formatting with either style. Wider locale/value/scale/offset crossproducts, other styles/collations, invalid text grammars, untyped NULL and arbitrary SQL source evaluation remain uncaptured.

## Explicit sessions, prepared inputs and observed distinctions

Each language section executes and retains `SET LANGUAGE ...; SET DATEFORMAT ymd; SET DATEFIRST 7; SELECT @@LANGUAGE,@@DATEFIRST`. Each prepared record also retains its own actual `contextSql` and complete result. The declared settings are inputs, not process defaults. SET LANGUAGE INFO messages, raw server/procedure identity and completion tokens remain unchanged. DATEFORMAT is deliberately fixed to ymd after the language change; DATEFIRST is fixed to 7. Effects of changing those two settings independently remain unmeasured.

For the captured midnight DATETIME input, default ANSI CAST is `Jan  2 2024 12:04AM` in us_english and `janv  2 2024 12:04AM` in French. German's January sample is `Jan  2 2024 12:04AM`; all twelve German months remain separately retained. This disproves an unconditional English month table for all sessions. Numeric modern-family output and default/style/function distinctions are independently retained; the fixture is the source of expectations, not a guessed formatting formula.

There are 75 admitted SQL construction failures per run: fifteen roles for each of two invalid DATETIMEOFFSET local/UTC extrema and fifteen roles in each of three languages for a SMALLDATETIME maximum that rounds beyond its range. Their complete diagnostics, empty result sets and separate successful reuse requests remain in the fixture. They are not removed, turned into NULL, or counted as formatter success.

Prepared single-control programs use original driver DATE, TIME(7), DATETIME2(7), DATETIMEOFFSET(7), DATETIME, SMALLDATETIME and UNIQUEIDENTIFIER declarations. Legacy programs repeat in all three languages; the other five families use us_english. Five independent roles per family/language give 55 prepares. Each executes first/typed-NULL/changed/first replay bindings, then unprepares; all 220 execution descriptor sets equal their actual prepare descriptor sets.

Prepared temporal intent retains UTC ISO input and the driver's singular `nanosecondDelta` explicitly. This differs from the plural property on decoded native dates. Connection `useUTC:true` is explicit. The driver's DATETIMEOFFSET encoder uses the host timezone offset despite that option, so the generator requires both admitted Date inputs to have offset zero before any container and documents `TZ=UTC`. Prepared nonzero offsets remain uncaptured; signed offsets are SQL-source controls. No driver input is silently changed to obtain a desired output.

TYPE_INFO, value length and parameter payload are retained for every binding. A local wrapper traces the bytes actually yielded once by each original typed encoder during sp_execute, preserving rather than regenerating the outgoing value for execution. The emitted trace reconciles with declaration/binding wire evidence. Every native prepared stored byte value independently matches that trace: DATE/GUID directly, modern temporal storage with its scale-7 prefix, and legacy fields with SQL storage byte order. NULL remains NULL. Fractional DATETIME2(7) emits payload `071768b71980460b`, stores `07071768b71980460b` including the scale prefix, and returns DATEPART nanosecond 123456700. These checks use explicit storage/encoding contracts, not a lossy Date or inferred offset.
