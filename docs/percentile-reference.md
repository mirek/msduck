# Percentile windows: SQL Server reference

The [pinned SQL Server 2025 capture](../reference/percentile-reference.json) contains 35 ordered requests in each of two fresh databases. An independent container replay matched both retained runs exactly. The [capture script](../scripts/capture-percentile-reference.mjs) fixes the request plan, image digest and fixture SHA-256 (`618a007ffa8ac0362c189579cc146ecde3704a26d7de5f8e5b32c1e24507d12b`). It retains full rows, typed TDS descriptors, ordered diagnostics and token events, and raw DONE status and command words. The captured server reports version `17.0.4065.4` from image `mcr.microsoft.com/mssql/server:2025-latest@sha256:86cc6144ef39bb0fbed2329e1ad79b13ee82e7b2e4739213a0db0800e668a74a`.

On four integer values 1 through 4, `PERCENTILE_CONT(.5)` returns 2.5 and `.25` returns 1.75 for every row, both with `FloatN(8)` metadata. `PERCENTILE_DISC(.5)` returns 2 with `Int` metadata. On DECIMAL(10,2) values 1.00 and 1.01, continuous interpolation returns 1.005 as `FloatN(8)` while discrete selection returns 1 as `DecimalN(17,10,2)`. FLOAT values 0.1 and 0.2 yield the observable double value `0.15000000000000002`; the fixture keeps that value instead of rounding it. BIT values 0 and 1 produce continuous 0.5 as `FloatN(8)` and discrete `false` as `BitN(1)`.

`PERCENTILE_DISC` accepts the tested VARCHAR(8) and DATE order expressions, returning the lower of two values with corresponding `VarChar` and `Date` descriptors. `PERCENTILE_CONT` rejects both with error 402, state 1, class 16: `The data types numeric and varchar/date are incompatible in the percentile_cont operator.` This rejection also occurs for an empty VARCHAR input, before result metadata. Both valid functions return a typed empty result set on an empty integer source: `FloatN(8)` for continuous and `Int` for discrete.

NULL order values are ignored in the tested four-row tie case; both functions return 1 on every row, including the row whose input was NULL. Discrete output then carries nullable `IntN(4)` metadata. Partitioning produces independent percentiles: 1.5 and 10 for continuous, 1 and 10 for discrete, over the two tested partitions. Descending order changes rank direction: at fraction 0 both functions return 4; at fraction .5, continuous returns 2.5 and discrete returns 3.

Fractions -0.1, 1.1 and NULL produce error 8727, state 1, class 16 in both percentile functions: `Input parameter of percentile function is outside of range [0, 1].` These requests emit column metadata and ORDER before ERROR, then DONE status 2/command 193 with no rows. The result descriptor is `FloatN(8)` for continuous and `Int` for discrete on the tested integer source. A character literal `'0.5'` converts successfully in the tested continuous query and returns 2.5. In contrast, incompatible continuous order types fail before metadata and emit ERROR then DONE status 2/command 253.

Prepared INT and NVARCHAR order expressions were rebound on the same handle. An INT parameter used as the order expression prepared with `FloatN(8)` metadata; bindings 2, NULL, 4, then 2 returned that value on each of four rows, including NULL for the NULL binding. `PERCENTILE_DISC` with an NVARCHAR(8) parameter prepared with `NVarChar(16)` metadata; bindings `a`, NULL, then `b` similarly returned the bound value on each row. The NULL execution used NBCROW tokens. Preparing `PERCENTILE_CONT` with an NVARCHAR(8) order parameter failed with 402 followed by 8180 (`Statement(s) could not be prepared.`). Successful prepares and executions emitted DONEINPROC status 17/command 193 then DONEPROC status 0/command 224; unprepare emitted DONEPROC status 0/command 224.

These are SQL Server observations, not claims of msduck parity. They cover the fixed expressions and bindings in the capture plan. They do not establish behavior for every numeric width, collation, mixed type, precision boundary, or diagnostic precedence when multiple independent query errors occur. The current implementation is described separately in [the percentile note](percentiles.md).
