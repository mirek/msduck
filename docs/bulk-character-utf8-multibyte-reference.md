# Deeper UTF8 reference controls

Task #930 captures original SQL Server 17.0.4065.4 BulkLoad outcomes for matching UTF8 VARCHAR(64) source TYPE_INFO and native UTF8 VARCHAR(64) storage. Every isolated table receives NULL and one byte challenge. Direct binary native readback and binary SQL UTF16 projection are separate from tedious display text.

The fixed 400-case matrix contains:

- 72 third-byte controls: leads E0/ED/EF, first continuations 80/9F/A0/BF, third bytes 00/7F/80/BF/C0/FF.
- 288 fourth-byte controls: leads F0/F4, first continuations 80/8F/90/BF, and all 36 combinations of those same six third/fourth bytes.
- 40 mixed inputs: xorshift32 seed `0x6d736475`, carrying state across cases; length cycles 0..31; each generated byte is the low eight bits after shifts 13 left, 17 unsigned right, 5 left.

Append byte 42 to every anchor. Mixed case names include their index, so repeated empty anchors retain separate identities. The new collector's explicit row guard is 64 hex characters (32 bytes); prior collectors remain unchanged. All declarations fit their 64-byte widths.

## Original observations

All 400 cases in each of four fresh databases succeeded: callback row count 2, no errors or informational diagnostics, original-session counters `[0,2,0,0]`, and exact native byte identity. ## Limits and next work

No general admission/error grammar, capacity rule, codepage conversion, assignment semantics or production support is established here. All challenge inputs have suffix 42 and bounded matching declarations. Failed earlier loads, fixed CHAR/NCHAR padding and MAX descriptor transitions remain separate evidence; they are not normalized away.
