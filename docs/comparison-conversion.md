# Comparison conversion

The six ordinary comparison operators (`=`, `<>`, `<`, `<=`, `>`, `>=`) now
share known integer/character type precedence. When both operand types are known
and belong to integer, character or NULL families, and at least one is integral,
both operands convert to the highest integer type before comparison.

Known types include declared variables/parameters, explicit casts, small integer
and character literals, and supported CASE/logical-function results. The shared
integer converter rejects fractional character values with 245, preserves exact
BIGINT values, and treats space-only character values as zero. NULL comparisons
retain three-valued logic. This applies wherever those operators occur, including
WHERE, ON, HAVING, control flow and the comparison generated by NULLIF.

The rule follows Microsoft's [type precedence documentation](https://learn.microsoft.com/en-us/sql/t-sql/data-types/data-type-precedence-transact-sql).
Tedious tests exercise each operator, prepared reuse after conversion errors,
NULLs, both operand orders, JOIN/HAVING/IF contexts, exact BIGINT comparison and
failed UPDATE atomicity.

IN/NOT IN expression lists also use the highest known integer type across the
tested expression and list entries when all types are known integer, character
or NULL. The original IN node is retained, preserving NULL/UNKNOWN semantics and
avoiding duplication of the tested expression. Tests cover prepared reuse,
fractional-text rejection, NULL entries, BIGINT precision, character-only lists
and failed DELETE atomicity. See Microsoft's
[IN reference](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/in-transact-sql).

Full source-column/function/arithmetic type inference, other type families,
IN subqueries, quantified comparisons, full CASE comparison coercion, padding and
collations remain unfinished. Unknown types retain DuckDB comparison behavior.
Live SQL Server differential validation remains outstanding.

BETWEEN/NOT BETWEEN now coerce the tested expression and both bounds to the
highest known integer type when all three are known integer, character or NULL
expressions. This follows the common-type implementation in the inspected
mssqlite reference (`packages/transpile/src/expression.ts`). The original
BETWEEN node remains intact, with one occurrence of each operand. Inclusive
bounds, reversed bounds and the interaction of FALSE with UNKNOWN follow the
[Microsoft BETWEEN reference](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/between-transact-sql?view=sql-server-ver17).
Client tests cover all three conversion positions, exact BIGINT boundaries,
NULL bounds, prepared reuse after error 245, control flow, and failed UPDATE
atomicity. Mixed-type coercion remains subject to live SQL Server differential
verification; column types and other type families still need inference.
