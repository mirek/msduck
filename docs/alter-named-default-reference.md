# Named DEFAULT on ALTER TABLE ADD: SQL Server reference

`reference/alter-named-default.json` retains two fresh-database runs against the pinned SQL Server 2025 image `mcr.microsoft.com/mssql/server:2025-latest@sha256:86cc6144ef39bb0fbed2329e1ad79b13ee82e7b2e4739213a0db0800e668a74a`. `scripts/capture-alter-named-default.mjs` creates only its own random container and databases, captures ordered TDS result columns, rows, errors, information messages, DONE events and request row counts, then removes those resources. The 72 observations in each run are raw; numeric object IDs are retained. Cross-run comparison binds only the catalog's table and constraint object IDs to their scenario names. Every other row value, descriptor, diagnostic and completion is compared exactly. A separate invocation captured two more fresh databases and matched both retained runs. No credentials are written to the fixture.

Each table has `id INT NOT NULL PRIMARY KEY, old_value INT NOT NULL`; populated tables begin with `(1,10),(2,20)`. The captured ALTER adds `new_value INT [NULL|NOT NULL] CONSTRAINT df_alter_* DEFAULT (7) [WITH VALUES]`. The table shows values of the two pre-existing rows immediately after ALTER. Each case then inserts `(3,30)` while omitting `new_value`; that future row always receives `7`.

| New column | Existing table | No WITH VALUES | WITH VALUES |
| --- | --- | --- | --- |
| `NOT NULL` | Empty | No rows; future row gets `7` | No rows; future row gets `7` |
| `NOT NULL` | Two rows | `7, 7` | `7, 7` |
| `NULL` | Empty | No rows; future row gets `7` | No rows; future row gets `7` |
| `NULL` | Two rows | `NULL, NULL` | `7, 7` |

All eight ALTER statements succeed. Their batch completion has one `done` event with no DONE_COUNT and no errors; the subsequent `SELECT` has a row-counted `done`. For the populated result, the new nonnullable column is a fixed `Int` descriptor with flags 8; the nullable column is `IntN(4)` with flags 9, even when WITH VALUES filled all existing rows. Empty results retain the same declaration-driven descriptors.

Each new column has `column_id = 3`, a nonzero `sys.columns.default_object_id`, and one named `sys.default_constraints` row. That constraint's `object_id` equals `default_object_id`; its `parent_object_id` equals the table ID and `parent_column_id` equals 3. `sys.objects` exposes the same constraint ID and parent with type `D `. The captured definition is `((7))`, and `is_system_named` is false. These relationships hold in both runs. Their numeric table and constraint IDs happened to match across these two fresh databases, but are compared by object identity rather than treated as implementation constants. The raw catalog query's 15 TDS descriptors remain in the fixture.

A second table trying to reuse an existing constraint name fails with error **2714**, state 5, class 16, followed by **1750**, state 1, class 16. An invalid integer default on a populated table fails with **245**, state 1, class 16, followed by **1750**, state 0, class 16. In both cases, the new column and constraint are absent afterward and the original row remains. A successful named ALTER inside an explicit transaction exposes its backfilled value and linked constraint before rollback; rollback removes both while preserving the original table and row. The exact error messages, line numbers, descriptors and completion events are retained, not summarized away in the fixture.

The current `crates/msduck-sql/src/ddl_syntax.rs` rejects named options on `ALTER TABLE ... ADD COLUMN`; `src/table_alter.rs` implements part of the unnamed default population path. PR #179 records named `CREATE TABLE` defaults in the runtime catalog, but does not make named ALTER legal and does not expose the captured `sys.default_constraints` view. Implementation should first preserve the named option through syntax and lowering, then perform population, column creation, constraint identity, parent linkage and failure rollback in one DDL transaction. Differential tests should replay all eight branches plus duplicate-name, invalid-default and explicit-rollback cases against this fixture, comparing values **and** TDS metadata/errors/completions. The validator, table ALTER adapter and runtime catalog files have other live claims; publish bounded implementation tasks only after those claims complete or the owner explicitly hands them off.

On a host with the pinned image, Docker, Node.js and dependencies installed, run `node scripts/capture-alter-named-default.mjs`. It writes a fresh capture under `artifacts/compatibility/alter-named-default-reference/` and compares it to the retained fixture without rewriting that fixture. Inspect the raw artifact if a future SQL Server image or client version changes behavior.
