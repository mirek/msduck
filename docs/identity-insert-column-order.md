# IDENTITY_INSERT with a later physical identity column

The [retained SQL Server 2025 capture](../reference/identity-insert-column-order.json) has 25 ordered observations in each of two fresh databases on the pinned image `sha256:86cc6144ef39bb0fbed2329e1ad79b13ee82e7b2e4739213a0db0800e668a74a`. The [capture script](../scripts/capture-identity-insert-column-order.mjs) records rows, typed column descriptors, diagnostics, ordered TDS events and raw DONE status/command words. It pins the fixture SHA-256 `339a0cfaa7396922bda74fdc5806296dcf9ac04db85d0273aeea3bcf78d9e9c4`, validates the case plan and behavior, and refuses fixture aliases, symlinks, hard links and image changes. It also replays in a separate reference container.

`dbo.late(v INT, id INT IDENTITY(10,2), note NVARCHAR(20))` places `id` second in physical column order. An implicit insert produces `(v,id,note) = (1,10,'base')`. With IDENTITY_INSERT OFF, explicitly listing `id` first or second returns 544/state 1/class 16 and a failed DONE with command 195; a positional `INSERT ... VALUES` without a column list returns 8101 and command 253. None changes the allocator. The quoted, case-varied `SET IDENTITY_INSERT [DbO].[LATE] ON` succeeds with command 183. Omitting `id` while ON returns 545/command 195.

With ON, listed `id` values 30 and 50 succeed when the identity is first and second in the source list. A quoted alias with list order `(note,v,id)` returns `OUTPUT inserted.id,inserted.v,inserted.note = (70,5,'alias')` with `Int`, `Int`, `NVarChar(20)` descriptors and command 195. The OUTPUT identity descriptor has flags 24. A direct SELECT of stored `id` has flags 16 while OFF and 24 while ON in this capture. A lower explicit ID 20 inserts a row but leaves `IDENT_CURRENT` at 70. After OFF, the next generated ID is 72. The final rows in identity order are IDs 10, 20, 30, 50, 70 and 72. Quoted/case-varied spellings therefore address the same tested table setting, and permission depends on catalog identity and source-column binding rather than a fixed first-column assumption.

This is SQL Server ground truth for those statements, not evidence that msduck executes IDENTITY_INSERT end to end. The merged [live preflight adapter](../src/identity_insert_write.rs) resolves physical position and source-column order, but the engine does not call it yet. This capture does not establish three-part names, temporary tables, triggers, computed columns, failed writes after source evaluation, concurrent sessions, or every INSERT source shape; the other IDENTITY_INSERT captures cover separate portions of those boundaries.
