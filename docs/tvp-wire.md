# SQL Server TVP RPC request wire evidence

`reference/tvp-wire.json` retains the decrypted, post-login outgoing TDS RPC
requests generated by tedious 20 against a pinned SQL Server 2025 image
(`17.0.4065.4`). The generator, `node scripts/capture-tvp-wire.mjs`, uses the
repository's isolated reference-container helper. It ran four cases in a fresh
database twice in each of two independent containers. All four complete request
captures, typed observations and callback results matched exactly across runs;
the fixture keeps every run and its explicit comparison result. It does not
normalize packet bytes or diagnostics.

The listener attaches to tedious's packetized `outgoingMessageStream` only after
login and only around each controlled procedure call. It accepts RPC packet type
`0x03`, caps the complete capture at 512 KiB, requires complete packets and a
final EOM, and parses the entire RPC request through its TVP value. LOGIN7,
PRELOGIN, TLS handshake data and credentials are outside this capture interval.
The fixture records raw packet hex and reassembled payload hex alongside parsed
procedure, parameter, TVP type name, metadata, row and cell fields. The callback
records SQL Server's acceptance or error; setup and product version are captured
separately.

The valid requests call `dbo.TvpProbeEcho` with `@rows` using the `dbo.TvpProbe`
table type. Its three columns are nullable INT, NVARCHAR(10) and VARBINARY(10).
The empty TVP returns count zero. A row with NULL Unicode and non-NULL binary
returns one; three rows with mixed NULL, empty binary and Unicode return three.
The valid TVP metadata has zero-length database and column names, schema `dbo`,
type `TvpProbe`, three columns and terminating `0x00` tokens. NVARCHAR(10)
advertises 20 bytes, while a NULL cell uses `0xffff` and an empty binary cell
uses zero length. These are observed request encodings, not server result-token
formats.

Passing JavaScript `null` as `TYPES.TVP` produces a request with empty schema/type
name and `0xffff` column count. SQL Server rejects it with error 8060: a null
TVP must be sent as a default parameter. The capture retains that rejection
without replacing it with an empty-table success. A separate default-status
probe is needed before implementing the SQL Server default TVP path.

On a Docker host with the pinned image and Node dependencies, run the generator
without flags to compare a fresh capture with the retained fixture. It writes a
separate diagnostic capture under `artifacts/compatibility/tvp-wire/`. The
`--write-fixture` mode creates a missing fixture and refuses to overwrite one.
Before starting a container, the generator also rejects a positional output
that resolves to the retained fixture, including symlinked path components and
hard links. An offline CLI check rejected all four alias forms while the
fixture's SHA-256 remained unchanged.
The original run used `linux.local`; a replay after adding explicit acceptance
assertions matched the retained fixture. The parser intentionally supports only
the captured INT/NVARCHAR/VARBINARY column shape. Other TVP types, order/unique
metadata, packet fragmentation, default-status encoding, stored-procedure
semantics beyond row counting and Rust server support remain unverified.
